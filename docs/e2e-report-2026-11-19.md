## How it was run

Docker is available on this machine. `supabase start` (CLI 3.2.0) brought up a local stack and applied every file in `supabase/migrations`, including `20261125000000_reward_tiers_and_homework_count.sql`. Studio, storage, realtime, analytics, and the other unused services were excluded. The local API is `http://127.0.0.1:54321` with the CLI's local demo keys. `supabase db reset` runs at the start of the script so each run begins empty.

One host detail: legacy iptables had `FORWARD` policy `DROP` while Docker wrote nftables rules, so containers could not reach each other and the first `supabase start` failed while applying the Realtime schema. The runner probes that path and, only if the probe fails, sets the legacy `FORWARD` policy to `ACCEPT`. After that, all eight migrations applied.

The app was `next dev` on `http://127.0.0.1:3000` with these flags on:

- `NEXT_PUBLIC_SERVER_AUTH`
- `NEXT_PUBLIC_WRONG_ANSWERS_SYNC_ENABLED`
- `NEXT_PUBLIC_PARENT_HOMEWORK_ENABLED`
- `NEXT_PUBLIC_REWARDS_ENABLED`

Playwright (Chromium, timezone `Asia/Singapore`) drove the UI. Accounts were `mrs.tan.e2e@example.com`, `mr.tan.e2e@example.com`, and student `amir_e2e`. Saturday is not the real clock (today in this run was Thursday 19 Nov 2026). For that phase only, the Next.js process loads `tools/e2e/saturday-clock.cjs`, which moves `Date` to Saturday 21 Nov 2026, 10:00 Asia/Singapore. GoTrue and Postgres keep the real clock. The browser does too, so the practice done on Thursday still falls inside that Saturday's Mon–Sat week.

### 6. Homework gate, and issue #32

Current behaviour, which matches the code and is what issue #32 is changing:

- No homework assigned for the day: eligible. The English daily credit (1) was written as soon as the first set was claimed.
- Homework assigned and unfinished: not eligible. After 12 questions were assigned, the Chinese set's claim wrote **no** Chinese credit row.
- Every assigned question solved (right or wrong counts as done): eligible. Solving the 12 and opening Today wrote the Chinese daily credit, 1 credit at 39%, still under the 19 Nov rule.
- There is no pending-credit row, no "Pending: finish today's homework" line, and no forfeit status. A credit that was confirmed before homework existed stays confirmed. A credit that was blocked is computed again on the next claim; it is not stored while it waits.

## Bugs

### 1. Accepting an invite reloads onto the login screen

Priority: high. The link itself is saved.

Repro: parent A invites parent B; parent B signs up with that email and presses Accept.

Expected: parent B stays signed in and the child appears on the dashboard.

Actual: Accept returns 200, `guardian_invites.status` becomes `accepted`, and `parent_child` gains the second row. About 800ms later the page reloads and shows "Welcome back". The `sb-127-auth-token` cookie is still there. Logging in again shows the child. Any full reload does this, because parent and student sessions live only in React state.

Suspected files: `src/app/ClaudeApp.js` (`App` restores an admin cookie via `adminSessionValid` and does not call `GET /api/auth/me` for a parent or student), `src/components/ParentDashboard.js` (`acceptInvite` calls `window.location.reload()`).

### 2. Credits are confirmed or skipped, never pending (issue #32)

Priority: product follow-up, already filed. Not a regression against the merged #30 behaviour. Claude's #32 work is the intended change. This run only records what the app does today. See scenario 6. No pending balance is shown to the parent or the student.

### 3. `verify_all_sets.py` flags one English editing item

Priority: low. Pre-existing content check, not touched by this test change.

Actual: `S12 E4` — the first `was` in the sentence is not the underlined spot (`위반 세트 1개`). `audit_hints.py` reported 0 hint-leak violations.

Suspected file: the S12 editing item in `src/data/p3/english/wa1_practice.ts` (generated; fix the source JSON and regenerate).

### 4. `tools/notify_selftest.mjs` expects the old email wording

Priority: low. Pre-existing. The dry-run assertion wants the email body to contain `❌ Chinese`. `src/lib/notify/emailTemplate.mjs` now writes `❌ Not done – Chinese: 0/1 sets`, and the payload is `children[]` rather than a flat `subjects` list. WhatsApp preview text still uses the old `❌ Chinese 0/1` shape, which is why only the email assertion failed.

Suspected files: `tools/notify_selftest.mjs`, `src/lib/notify/emailTemplate.mjs`.

## How to rerun

From the repo root, with Docker and the Supabase CLI installed:

```bash
bash tools/e2e/run-local.sh
```

That resets the local database, applies migrations, generates `tests/e2e/fixtures/similar.json`, and runs the three Playwright phases (flags on, Saturday clock, flags off). It refuses to start if any environment variable contains the production project ref.
